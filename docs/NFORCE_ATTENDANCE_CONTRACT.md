# QSwipe → NForce attendance contract v1 — offline only
No connection, endpoint, deployment, credential, scheduler or production migration is included. This is a proposed contract requiring approval by both owners, independent security and payroll/accounting review. NForce owns hours, compensation, statutory classification and payroll locks; QSwipe provides attendance status, not work duration.

Envelope: schemaVersion=1, source="qswipe", eventId UUID, tenantId UUID (approved mapping identifier), employeeId UUID (approved mapping identifier), sessionId UUID, revision positive integer, status present/absent/excused/unmarked, occurredAt canonical UTC ISO timestamp, previousDigest null for revision 1 or SHA-256 hex for later revision. No names, emails, auth IDs, QR, medical details, salaries or free text. An adapter must map roster history to approved employee identity, verify tenant mapping, only export authorized reconciled records, and never infer historical status. No direct database sharing. 
Canonical digest: SHA-256 of UTF-8 JSON array in the exact order documented in lib/integration/nforce-contract.js. Validate all fields and exact schema. Proposed transport HTTPS with mutual TLS or scoped service identity, detached signature over body digest plus audience, method, path, key ID, timestamp and unique nonce; independently review signature algorithm, replay window and key rotation. Durable consumer transaction must bind tenant, event ID and session/employee revision, reject changed event ID reuse, quarantine missing/out-of-order revisions and mismatched previous digest; exact replay is no-op. Append corrections, do not overwrite locked payroll or derive time worked from shift boundaries/status. Human reconciliation and approved adjustment workflow after lock. Dead-letter encrypted minimal data, bounded retries, no secrets in logs. 
Offline helper is not a durable consumer or authenticated transport. It validates identity scope and revision continuity using explicitly supplied mapping and prior receipt, not real credentials. No delivery implementation authorized. Both systems must separately implement durable idempotency, audit, rate limits, revocation, retention, purpose limitation and privacy approvals. Test fictional identities only.
