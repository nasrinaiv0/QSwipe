# QSwipe player collection, bingo and challenges — staging only
Parent PR #19 db705a28e93e6bfceaaa48a1254ee5a49e840723. No remote migrations, paid resources, production changes or merges. Reuse the existing versioned snapshot adapter, keeping the online backend default-off. No attendance or HR data in games.
Persistent player profiles: opt-in pseudonymous profile with random 256-bit recovery credential, stored as a hash server-side. Browser explicitly remembers profile on this device using localStorage; sign-out/forget removes it. Shared-device warning, no real names required, no email or account linkage. Profile survives room closure and process restart; no cross-device account recovery UI. Limit 250 profiles, 90 days since last activity, 20 tournament history entries per profile, 30 room rounds, bounded points. Only authenticated profile holder may read/edit own profile. Optional profile-bearing create/join commands, distinct from existing anonymous guest flow; bind profile once per room, no simultaneous duplicate profile seats in same room. Do not expose profile IDs/credentials/history to other players. Profiles and rooms share the existing snapshot CAS transaction: reserved envelope inside existing JSON array (max 99 rooms + one metadata record) avoids remote schema changes; legacy snapshots supported. No plaintext credentials in durable store. Unknown/malformed metadata fails closed. Preserve existing guest behavior.
Mascots: original vector-style collectible duck, fox, bunny, bear, and star characters; lightweight CSS bob/blink and reduced motion; server-authorized selection and unlock thresholds (completed rounds, points, bingo, tournament wins). No payment or randomized purchases. Cosmetic only. Profile lifetime counters increment once per finished game from room score delta; partial trivia at closure not credited. Daily challenge: complete one eligible game per UTC day (at least one submitted trivia answer, matched memory pair or bingo mark; random wheel/race excluded). Award 25 profile-only bonus once on settlement, no room leaderboard impact. Track current UTC day using server clock; no backdated claim. 
Bingo: independent 5x5 boards, free center, server draws unique numbers 1–75 every 900ms after start; server validates marks only for called numbers on own board, no duplicate scoring, win on any full row/column/diagonal. First valid completed line ends round immediately, winner +40 room points; deadline after 75 calls plus 15s; no speed prize beyond first valid line, no money. Server owns outcomes and clock, UI shows calls and board, no other player's board. 
Tournament history: persist bounded own participation result and winner flag on completed tournament, support custom trophy name (32 chars) and style from existing choices. Never overwrite historical receipt. Keep existing room tournament rules. Guest profiles remain optional.
Acceptance: unit tests for profile isolation, restart, CAS, daily reward, bingo validation, history, collection unlock, guest regression; actual browser captures across independent sessions with persistent profiles and bingo. Existing CI and disposable PostgreSQL unchanged. Preview-only online adapter remains inactive unless explicitly authorized staging database configuration. Independent Claude review instructions, no claim executed. No release authorization.
