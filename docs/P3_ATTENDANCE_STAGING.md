## Design and threat model
- Review-only SQL candidate under supabase/staging, deliberately outside automatically discovered migrations. Execute only in disposable CI PostgreSQL; no remote apply. Private data tables have RLS enabled and no client grants. One private fixed-search-path privileged command and a public SECURITY INVOKER RPC wrapper; no service key. Both direct RPC and Vercel requests must enforce the same DB authorization. A DB enable flag defaults OFF; API additionally requires preview + independent project refs + explicit P3 flag.
- Trusted admin creates bounded UTC sessions scoped to a workspace/unit. No user-facing scheduling or manager write grants. One immutable initial attendance result per session/roster (present/absent); unmarked is distinct, version zero. P4 corrections, approval workflow, and payroll expressly excluded.
- Check verified nonanonymous user and current auth.sessions row, active target and actor memberships, active workspace/unit, exact manager unit grant + provider AAL2 for marking. No manager self-mark. Share-lock authorization rows so concurrent revocation serializes; session/roster pair advisory transaction lock plus unique constraints. Lock actor/request key for idempotency, compare full canonical command including QR hash, reject reuse with different payload. Recheck authorization before replay. Server timestamps only. No last-write-wins; stale version returns conflict; client resyncs authoritative snapshot and uses same request key for ambiguous network retries. Offline client integration is not included.
- Own QR issuance only: unpredictable opaque token, hash stored, bound to session and roster, short expiry capped by session close, rotating previous unconsumed pass, single use, QR-present only. Manager confirms in person; screenshot forwarding remains possible within expiry. No QR/token in logs or audit. No offline QR redemption.
- Initial manager manual marking requires enumerated reason (in-person/roll-call/verified absence); no free-text PII. State, consumed pass and append-only event commit together. Trigger forbids update/delete of audit events; DB owner can alter/disable triggers, so not tamper-proof against privileged operator. No client access to private event or token tables.
- Mocked API tests + actual PostgreSQL 17 tests with auth stubs, two fictional tenants, revoked session/actor/target, AAL1/AAL2, role scope, QR expiry/rotation/replay, idempotency mismatch, version conflicts, audit immutability and overlapping independent connections. CI never targets remote database.
- Review required before any remote use: actual Supabase Auth session semantics, RLS grants, PostgREST exposure, API rate limits, audit retention, admin scheduling and device/browser acceptance. No production release.
