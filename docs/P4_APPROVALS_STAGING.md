## Contract
- Independent P4 database flag defaults OFF; preview API additionally requires existing P3 flag and P4 flag. No service key. Reuse P3 authorized read command, which locks live identity/session, target membership, workspace/unit, manager grant and session/roster pair. P4 additionally requires checker AAL2 and different user from both maker and attendance subject. Scope is exact unit; role or identity is never accepted from request JSON. Read/list restricted to same authorized pair. Requests by subject or authorized scoped manager, existing attendance only, different proposed status, enumerated reason only. No free text or private attachments.
- Immutable request and decision rows; one decision per request. Original P3 event remains unchanged. Approval updates current projection to version N+1 and adds decision/history atomically; rejection leaves projection unchanged. Require expected attendance version on request, recheck current version and old status on approval, stale request rejected without changing history. P3 read API must accept corrected versions; P3 original-mark idempotent replay returns original historical receipt, not current state (read to resync).
- Caller-generated correction UUID is idempotency key, compared against exact actor/pair/version/proposal/reason. Decision retry only by same checker with same outcome/reason; mismatched replay conflicts. Pair lock shared with P3; one decision and one approved transition per pair/version backed by unique indexes. Recheck authorization on replay. No self approval, including a manager correcting their own attendance. Maker must retain active membership and, when not subject, current explicit unit grant when decision is made. Lock these rows. Requests/decisions allowed within 30 days of session close; no automatic approval.
- Private RLS tables with zero client table privileges. Narrow private fixed-search-path privileged function; public invoker wrapper only. Triggers prevent UPDATE/DELETE/TRUNCATE of request and decision history (not tamper-proof against DB owner). No attendance deletion, payroll, leave request workflow, UI wiring or offline client queue in this PR. Pair-specific list capped at 50 with stable cursor planned separately if needed; returns minimal workflow metadata.
- Test actual PostgreSQL 17 with fictional tenants, scoped manager/maker/checker, stale versions, revocation, replay, rejection and overlapping independent connections. Mocked API fail-closed and field projection tests. Actual Supabase provider/PostgREST integration, rate limits, audit retention, independent review and physical-device tests remain release gates.
