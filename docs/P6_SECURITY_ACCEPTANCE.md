## Threat model and implementation
- Optional durable correction vault: explicit device opt-in after verified identity, separate strong passphrase (minimum 16 characters, recommend five random words), Web Crypto PBKDF2-HMAC-SHA256 600,000 iterations, random 16-byte salt and unique random 12-byte AES-GCM IV, 256-bit nonextractable key, AAD binds format/account/project. Only ciphertext + bounded envelope persisted; no bearer, QR, email, names, decisions or keys. Account namespace hashed; Web Locks exclusive per vault, fail closed if unsupported or another tab owns it. Restore only after reauthentication + matching passphrase. Wrong key or corruption never overwrites existing vault. Drafts expire after seven days from creation; purge expired when unlocked. Device storage can be cleared/evicted; no offline cold start. No guarantee against active XSS, malware or malicious browser extensions. Logout locks, explicit deletion removes ciphertext; no recovery if passphrase forgotten. User must save successfully before sending durable drafts, persist result on sync, use original idempotency key on ambiguous delivery. No background sends. Memory-only fallback explicitly indicated, never silently overwrite a locked vault.
- Consolidated inbox: gated private SQL candidate, authenticated AAL2, verified current session, exact workspace/unit grant, active subject and original maker membership, exclude self/maker, pending within correction window. Stable descending keyset cursor, page size 20, bounded response, indexes, minimal display fields. Read snapshot not authority to approve; use existing P4 transaction. No API service key. No offline decisions. All remote enable flags remain OFF.
