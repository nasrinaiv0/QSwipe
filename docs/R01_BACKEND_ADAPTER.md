# R01 authenticated adapter — preview-only, release HOLD
Base PR #12 c81a3d3509858ded1bc7cdab12fc96c5a2113fb3. Keep all prior PRs unmerged. No remote migration, resource creation, production settings or promotion.

## Design
Reuse P0–P6 staging auth, MFA, roster, sessions, approval inbox, history and encrypted outbox. Provide an explicit authenticated workspace entry in the existing main welcome, desktop and mobile app chrome. Full-page navigation isolates the demo runtime and its client-side role picker from the verified workflow; no iframe, local-store bridging, demo import, or silent fallback. Use QSwipe familiar Today/Attendance/Approvals/Reports navigation, green neutral tokens and accessible responsive controls in the authenticated shell. The root remains explicitly marked local demo; separate origin for real data remains a release gate (same origin in preview). Never weaken stagingConfiguration production guard. Independent adapter flag defaults off.

## Attendance and reporting
Use selected authorized employee/session and P3 RPC only: own unmarked pass issuance; manager with scoped MFA grant may manually mark present/absent or verify single-use pass after in-person identity check. QR encodes only opaque 64-hex pass; no names, JWT, URL or demo QR. Existing uqr dependency generates bounded QR matrix on issue response. SVG via DOM, no HTML injection; manual token entry is universal fallback; optional image/native scan only where browser supports it, physical camera and jsQR fallback remain acceptance gates. Clear pass/token on selection, expiry, logout and hide; never persist. No offline marking or approval. Fixed request ID on ambiguous mark retry; definitive denial requires refresh, no optimistic state. Existing P4/P6 approval flow reused. Report is explicitly selected employee's bounded recent server-discovered sessions (max 30), not payroll or full workspace totals; present/absent/unmarked counts, marked denominator and completion of listed sessions only, no historic scheduling inference. Report refresh re-reads server. No new SQL, no server admin onboarding or scheduling implemented.
